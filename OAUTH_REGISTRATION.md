# Регистрация OAuth-приложения «MultiAI Mobile IDE» в MultiAI

Эта инструкция — для **владельца MultiAI**: как зарегистрировать OAuth-клиент,
который использует Android-приложение **MultiAI Mobile IDE**, чтобы в нём
заработал вход через MultiAI.

Без этой регистрации кнопка «Войти через MultiAI» в приложении будет
возвращать ошибку — `client_id` не опознаётся сервером.

---

## 1. Где регистрировать

1. Откройте **`https://multiai.store/dashboard`** под учётной записью
   администратора.
2. Перейдите в раздел **OAuth → Приложения**.
3. Нажмите **«Создать приложение»** (или «New application»).

---

## 2. Что вводить в форму

Заполните поля **точно так, как ниже** — эти значения захардкожены в
приложении и должны совпасть с регистрацией символ-в-символ.

| Поле формы | Значение |
|---|---|
| **Название приложения** | `MultiAI Mobile IDE` |
| **Тип клиента** | `Native` (мобильное/десктоп приложение) |
| **Confidential (есть client_secret)?** | `Нет` (native public client — секрета нет по RFC 8252) |
| **Redirect URI** | `multiai-mobile://oauth/callback` |
| **Разрешённые scopes (права)** | `openid` `profile` `email` `account:read` `keys:read` `ai:invoke` |
| **Обязательный выбор API-ключа** | по желанию¹ |
| **Device Authorization Grant** | `Нет` (на Android есть системный браузер, device flow не нужен) |

¹ Если включите **обязательный выбор ключа** — каждый запрос к модели
(`ai:invoke`) будет требовать, чтобы пользователь сначала выбрал один из своих
API-ключей. Если выключите — сервер использует managed fallback-ключ
автоматически. Для IDE обычно **включают** (так видно расход по конкретному
ключу). См. §8.1 контракта интеграции.

### Важные нюансы

- **Redirect URI** должен совпадать символ-в-символ: схема `multiai-mobile`,
  host пустой, path `/oauth/callback`. Никакого `https://`, никаких портов,
  без query/fragment. Это custom scheme, разрешённая для native-приложений по
  §2 контракта.
- **Не генерируйте и не записывайте `client_secret`** — для native-клиента его
  не существует. Если форма требует секрет, значит выбран неверный тип клиента
  (должен быть Native/Public, а не Confidential/Web).
- **Не меняйте scopes** после того, как пользователи уже авторизовались —
  по контракту §3 изменение разрешённых прав отзывает все старые grants,
  access- и refresh-токены. Все пользователи должны будут войти заново.

---

## 3. Что вернёт форма после создания

После сохранения MultiAI выдаст **`client_id`** (одна строка вида
`ma-client-…`). Это **не секрет** — он зашит в приложение и передаётся
открыто в form body при обмене кода (§5.4 контракта).

**Скопируйте его** — он понадобится на следующем шаге.

---

## 4. Передать `client_id` разработчику приложения

Вставлять `client_id` в код будет **разработчик приложения** — вам в код
лезть не нужно.

Отправьте скопированный `client_id` разработчику **в Telegram**:

Достаточно переслать одну строку вида:

Разработчик сам подставит значение в конфигурацию сборки, пересоберёт APK и

> ⚠️ `client_id` — **не секрет** (это публичный идентификатор native-клиента),
> поэтому передавать его в открытом Telegram-сообщении безопасно. Никакого
> `client_secret` для этого приложения не существует — не прикладывайте его
> к сообщению даже если форма его покажет.

## 5. Проверить, что всё совпадает

Сверьте три значения «форма ↔ приложение» (это сделает разработчик, но для
контроля можно проверить и владельцу):

| Значение | В форме MultiAI | В приложении (у разработчика) |
|---|---|---|
| Redirect URI scheme | `multiai-mobile` | `multiai-mobile://oauth/callback` |
| Redirect URI path | `/oauth/callback` | (часть URI выше) |
| Scopes | `openid profile email account:read keys:read ai:invoke` | та же строка в конфиге |

Любое расхождение → сервер вернёт `invalid_redirect_uri` или `invalid_scope`.

---

## 6. Пересборка и проверка (делает разработчик)

Пересборку APK, установку на устройство и end-to-end проверку входа берёт на
себя **разработчик приложения**. От владельца после регистрации требуется
только передать `client_id` (см. раздел 4).

Когда разработчик вернёт собранный APK, владельцу достаточно:
1. Установить APK на тестовое устройство.
2. Открыть экран профиля, нажать **«Войти через MultiAI»**.
3. Убедиться, что открывается системный браузер со страницей
   `multiai.store/oauth/authorize`, вход проходит, и профиль в приложении
   заполняется.

Если на странице согласия видно название **«MultiAI Mobile IDE»** — регистрация
применена корректно.

---

## 7. Что произойдёт при первом входе пользователя

1. Приложение открывает системный браузер → `multiai.store/oauth/authorize`.
2. Пользователь входит в MultiAI (если включена 2FA — сервер сам запросит
   passkey/TOTP, приложение в это не вмешивается).
3. Пользователь видит список запрошенных прав и **разрешает** доступ.
4. MultiAI редиректит на `multiai-mobile://oauth/callback?code=…&state=…`.
5. Приложение ловит callback, проверяет `state`/`iss`, обменивает код на
   токены, валидирует ID token по JWKS, сохраняет refresh token в
   Android Keystore (EncryptedSharedPreferences) и показывает профиль.

В списке **«Мои подключения»** (Security Center у пользователя на multiai.store)
появится запись с названием **«MultiAI Mobile IDE»** и `device_name`, который
приложение передаёт в авторизационном запросе.

---

## 8. Где показывается название «MultiAI Mobile IDE»

После регистрации название **«MultiAI Mobile IDE»** видно пользователю в трёх
местах:

1. **Страница согласия** (`/oauth/authorize`) при первом входе —
   «MultiAI Mobile IDE запрашивает доступ к: …».
2. **Security Center** пользователя (`multiai.store/dashboard` → Безопасность →
   Подключения) — список всех OAuth-подключений с названиями.
3. **Само приложение** — отображается как заголовок на экране входа
   (зашито в ресурсы приложения, не зависит от формы регистрации).

---

## 9. Управление подключением после регистрации

| Действие | Где | Эффект в приложении |
|---|---|---|
| Изменить scopes | Dashboard → OAuth → MultiAI Mobile IDE | Все старые токены отзываются, пользователи должны войти заново |
| Отключить приложение | Dashboard → OAuth → MultiAI Mobile IDE → Delete | Все подключения отзываются немедленно |
| Пользователь отзывает подключение | Security Center пользователя | Приложение при следующем запросе получает `invalid_token` и переходит в signed-out состояние |
| Сменить пароль / отключить MFA | Настройки аккаунта | По контракту §12 подключение может быть отозвано автоматически |
